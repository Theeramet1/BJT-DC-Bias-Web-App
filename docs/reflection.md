# Reflection — Lab 02

## 1. ทำไมการเปิด `templates/index.html` ตรง ๆ จึงไม่เท่ากับการรัน Flask?

เพราะ `index.html` เป็น **Jinja template** ไม่ใช่หน้าเว็บที่สมบูรณ์ ในไฟล์มี
`{{ ... }}` และ `{% %}` ซึ่งเบราว์เซอร์ไม่รู้จัก ถ้าเปิดด้วย `file://`
เบราว์เซอร์จะแสดงโค้ดพวกนั้นออกมาดิบ ๆ เช่น `{{ '%.3f'|format(result.vb) }}`
และไม่มีอะไรถูกคำนวณเลย

เมื่อรันผ่าน Flask เกิดสิ่งที่ต่างออกไปสามอย่าง

1. Flask รับ HTTP Request แล้วเลือก view function ที่ตรงกับ route
2. view function เรียก `dc_bias.operating_point(...)` ให้ Python คำนวณ
3. Flask เอา `BiasResult` ไปให้ Jinja render เป็น HTML จริง แล้วส่งกลับ

สรุปคือ `index.html` เป็นเพียง **แม่แบบ** ส่วนโปรแกรมที่ทำงานจริงคือ
`app.py` + `dc_bias.py` ที่ต้องมี process ของเซิร์ฟเวอร์คอยรันอยู่

## 2. ฟอร์มส่งข้อมูลไป Python อย่างไร?

1. ผู้ใช้กด **Calculate DC Bias** → เบราว์เซอร์อ่านค่าใน `<input name="...">`
   ทุกช่อง แล้วสร้างชุดข้อมูล `name=value`
2. เบราว์เซอร์ส่ง **HTTP POST** ไปที่ `/calculate` โดยข้อมูลอยู่ใน request body
   (`application/x-www-form-urlencoded`)
3. Flask จับคู่ path `/calculate` กับฟังก์ชัน `calculate()`
4. ในฟังก์ชัน อ่านค่าด้วย `request.form.get("vcc")` — ได้มาเป็น **สตริง**
   ไม่ใช่ตัวเลข จึงต้องผ่าน `parse_form()` เพื่อ `float()` และตรวจช่วงค่า
5. ถ้าผ่าน ส่งต่อให้ `dc_bias.operating_point(...)` คำนวณ
6. `render_template` คืน HTML กลับไปเป็น HTTP Response

จุดที่พลาดง่ายคือขั้นที่ 4 — ค่าจากฟอร์มเป็นข้อความเสมอ `"12"` ไม่ใช่ `12`

## 3. แก้สมการใน `dc_bias.py` แล้วต้องแก้ HTML หรือไม่?

**ไม่ต้อง** ตราบใดที่ยังคืนค่าเป็น `BiasResult` ที่มี field ชุดเดิม

สาเหตุเพราะ template แยกตัวเลขออกจากสมการแล้ว มันแค่พิมพ์
`{{ '%.3f'|format(result.vce) }}` — ไม่รู้ว่า `vce` มาจากสมการใด
ถ้าแก้ค่าคงที่หรือปรับลำดับการคำนวณ ผลลัพธ์ใหม่จะไหลออกมาที่หน้าจอเอง

ต้องแก้ HTML เฉพาะกรณีที่ **interface เปลี่ยน** เช่น

- เพิ่ม field ใหม่ใน `BiasResult` (เช่น `power_dissipation`) → ต้องเพิ่มบรรทัดแสดงผล
- เปลี่ยนชื่อ field → template จะ error เพราะหาตัวแปรไม่เจอ
- เปลี่ยนหน่วยที่คืนออกมา → ตัวคูณใน template (`* 1000`) ต้องแก้ตาม

การแยกแบบนี้ทำให้แก้ฟิสิกส์ได้โดยไม่ต้องแตะ HTML และแก้หน้าตาได้โดยไม่ต้อง
แตะสมการ ซึ่งเป็นเหตุผลที่เทสต์สองชุดแยกกันอยู่ (`test_dc_bias.py` กับ
`test_web.py`) — แก้สมการแล้วรันชุดแรกก็รู้ทันทีว่ายังถูกต้อง

## 4. ทำไมผลใน Region ที่แบบจำลองใช้ไม่ได้จึงต้องมี Warning?

เพราะสมการที่ใช้ทั้งหมดตั้งอยู่บนสมมติฐานว่า **ทรานซิสเตอร์อยู่ในช่วง
Forward-Active** ซึ่งแปลว่า

- รอยต่อเบส–อีมิเตอร์ไบอัสตรง และมีกระแสเบสไหลจริง
- รอยต่อคอลเลกเตอร์–เบสไบอัสย้อน (VCE ยังสูงพอ)
- β และ VBE คงที่ตามที่สมมติ

เมื่อสมมติฐานข้อใดข้อหนึ่งเป็นเท็จ สมการยัง **คำนวณออกมาเป็นตัวเลขได้**
แต่ตัวเลขนั้นไม่ตรงกับวงจรจริงอีกต่อไป

- **Cutoff:** ถ้า VTH ≤ VBE สมการจะให้ IB ติดลบ ซึ่งเป็นไปไม่ได้ทางกายภาพ
  ทรานซิสเตอร์ดับ สมการจึงไม่มีความหมาย
- **Saturation:** ถ้า VCE ต่ำกว่า ~0.3 V รอยต่อคอลเลกเตอร์–เบสไบอัสตรงแล้ว
  กระแสคอลเลกเตอร์ถูกจำกัดด้วยวงจรภายนอก ไม่ใช่ β อีกต่อไป ค่า IC = βIB
  จึงใช้ไม่ได้

ถ้าโปรแกรมแสดงตัวเลขโดยไม่เตือน ผู้ใช้จะเข้าใจว่าเป็นผลที่เชื่อถือได้ และอาจ
เอาไปใช้ออกแบบวงจรต่อ ซึ่งอันตรายกว่าการบอกว่า "คำนวณไม่ได้" มาก

ดังนั้นการเตือนไม่ใช่การตกแต่ง แต่เป็นส่วนหนึ่งของความถูกต้อง — ตัวเลขที่มา
จากแบบจำลองที่ใช้ไม่ได้ ต้องถูกกำกับด้วยข้อจำกัดของมันเสมอ ในโค้ดจึงแยก
`region` ออกจาก `warnings` และให้ template แสดงแบนเนอร์เมื่อ `warnings`
ไม่ว่าง
